# 声音导演：从听觉意图到逐段执行

在用户要求声音导演、创作节目／声景、细化表演或规划长内容时读取。先读 prompt-writing 的范围规则，再按需读 speech 或 sound-design。简单逐字朗读不必套完整流程。

## 导演的职责与能力边界

创作任务中主动决定对听众有意义的细节，不把“自然、电影感、有感染力”留作空泛口号。已有稿件可细化其已授权的表演和编排，但台词、歌词、事实、语言、参考音顺序、禁止项与用户指定风格不变。用户要求纯人声、纯音乐或单一音效时，用这个范围内的变化设计，不额外加声音种类。

区分三种依据：模型文档明确支持的人物描述、引号内台词、表演、背景与事件顺序；导演经验提出的节奏、层次、音色和张力设计；实际音频编辑才能落实的精确时间、声像、响度和接缝。后两者不能冒充模型的硬控制参数。音乐与歌曲方向沿用项目实践，不把其它音乐模型的参数移植到 Foleyix 当前接口。

## 1. 建立一份短声音设定

先确定本段要让听众**注意什么、感受什么、理解什么**，再选声音。复杂作品在内部或制作稿里维护以下设定，只把影响本次生成的内容写进提示词：

- 人声身份：角色名、音区与质感、发音／专名读法、主讲和接话职责、实际参考音映射。相邻角色至少有一项清晰听觉差异。
- 表演基线：通常的语速、句尾习惯、情绪克制程度；局部变化不改变身份。
- 听觉视点：听众在主播近处、房间一侧或场景外；空间大小、距离与反射感保持一致。
- 声音层次：主要信息在前景；中景承载必要事件；背景提供空间或情绪。没有需求的层次留空。
- 能量曲线：进入、发展、关键变化和退出；哪里留白，哪里增强，增强后如何回落。

例如电影讲解的主讲负责线索和解释，接话者负责疑问与理解转折；不能整期都悬疑耳语，也不能每句都做预告片式重音。前述选择是针对本次内容的设计，不是所有播客的默认配置。

## 2. 把情绪落到具体一句

根据这句的意图选择少量表演指令：

| 维度 | 可执行的声音说明 |
| --- | --- |
| 交流对象与目的 | 向搭档追问、向听众解释、克制地警告；避免只有情绪标签 |
| 强度与距离感 | 平常交谈、收低声音但仍清晰、提高力度而不喊叫 |
| 速度与节奏 | 铺设线索时稍慢，关键判断短促，解释因果时恢复平稳 |
| 重音与停顿 | 点明具体词；在揭示前短停，句尾留给另一人接话 |
| 发音与句尾 | 专名清楚、疑问句轻微上扬、确认句自然落下 |
| 呼吸与动作声 | 仅在剧情需要或用户授权时点到一处；不默认每句喘息、笑、叹气 |

如“在‘出口’前稍停，重读这个词，句尾收低”，比“极其紧张又自然”更具体。指令写在引号外，不把符号、呼吸声拼进原台词。少量关键句改变，其余保持基线；连续强情绪会消耗层次。

对话先决定谁发起、谁承接、何处转换话题。通常等前一句落下再接；打断／重叠只在授权剧情里使用，不能同时要求重叠和每句话绝对清楚。亲密感可以来自近距离和简洁回应，不需要擅加语气词。

## 3. 安排可辨认的声音层次与空间

优先让听众听清主体。每个必要声源写清来源、动作或持续状态、材质／频段质感、距离、空间、进入与退出，不把所有属性强塞给每个声源。

- 有对白：人声近而清楚，背景降低存在感；强瞬态放在句间，关键台词前减少背景变化。用“对白时退后，间隙轻轻显现”表达避让，不声称已实现自动 ducking。
- 空间：小房间短而轻的反射、空仓库较长余响、室外开阔感是方向。近远变化应有原因，不让主播无故从干声跳到大厅。
- 场景视点：走近、背向或隔门时，按叙事顺序写距离／遮挡变化。声像移动仅是提示，不能承诺固定坐标或真正双耳录音。
- 留白：关键转折可先收掉已允许的背景，再让一句台词落下；“声音变少”也能表达张力。纯人声节目只用人声节奏与停顿设计留白。

不要为“真实”自动制造底噪、爆音、齿音或呼吸瑕疵。需要电话、广播或旧录音质感时，保留语音可懂度，并确认符合题材与用户范围。

## 4. 按声音类型选择控制重点

| 类型 | 导演重点 |
| --- | --- |
| 旁白／电影讲解 | 信息节奏、段落重点、解释与悬念的差异、专名清楚；已有原文全部读出 |
| 播客／对白 | 角色身份和关系、接话间隙、情绪回应、章节转折；不是两人轮流念同一种语气 |
| 广播剧／声景 | 听觉视点、动作因果、前后景和事件顺序；音效不能提前泄露剧情或盖过关键句 |
| 单个／游戏音效 | 起音、主体和尾音的辨识度；动作与材质、重量和距离；重复使用时避免过长余响 |
| 环境／ASMR | 稳定背景床与稀疏事件、近远纹理、接近／离开方式；避免突然的高能事件 |
| 纯音乐／配乐 | 动机、配器职责、节奏密度、张力与收束；对白下方降低旋律竞争，只在有对白时要求避让 |
| 歌曲 | 主歌／副歌的演唱力度与配器差异、咬字、乐句呼吸、伴唱是否需要、结尾；歌词与唱法说明分开 |
| 角色音色设计 | 稳定身份与可复用性；用短预览检查目标特征，场景情绪不永久写进身份 |

声音类型的具体模型／CLI 边界见相应分支。跨段歌曲的旋律、调性和唱法连续性不能靠相同描述就保证。

## 5. 长内容采用分段导演，而非只在开头下指令

维护短连续性记录：角色身份与参考音顺序、发音表、空间、已允许的背景／配器、当前情绪、上一段结束状态。每段记录“叙事目的 → 起始状态 → 关键表演／声响变化 → 结束及下一段承接”。同一节目不在每段重新欢迎听众、重述身份、重建全部氛围或明显收尾。

每条实际提交都自包含：只重复本段必要的角色和公共声音设定，然后给本段完整台词及变化。首段可以开场，中间段自然续接，末段才收束；已出现的背景如需继续，在后段明确保持同一来源与层次。提示词可以要求连贯，实际接缝仍需试听。

**CLI 超长自动分段保留文字，但不会理解剧情，也不会自动把开头的导演设定复制到每段。** 已有长稿可用自动分段保全文字；需要逐段导演时先写成预算内的独立输入，逐段使用相同角色／参考映射提交并记录各自请求 ID。一个独立输入仍超限时继续拆分并补齐必要指令；不要把整份制作说明只放在长文件第一段就声称后段已受控制。CLI 不自动合并、铺音乐或做节目混音；这些属于网站编排或实际后期工作。

每条完整请求最多 500 汉字且总计 2,000 Unicode code points，包括公共指令和服务器添加的参考音说明。导演文字占用同一预算：优先保留台词和关键变化，精简重复形容词，必要时增加段数。不要为了塞入指令删台词，或把分段建议当作已生成结果。

30 分钟节目先规划章节和全量稿件，再按上述预算细分请求；章节数不等于请求数。目标时长靠实际音频时长复核，不能用文字估算或“30分钟”一句保证。用户要完整节目脚本／全部提示词时交付全量分段，不能用大纲或第一段示例代替；只要示例时明确它覆盖的范围。

## 6. 交付与审听闭环

短任务交付可直接提交的提示词。复杂／长内容在用户需要制作方案时，可附短声音设定、按顺序的完整分段提示词，以及后期衔接说明；这些说明不混进要朗读的文字。用户只要提示词时不给多余说明，但仍在内部完成导演检查。

交付前用这次作品的具体目标检查：关键一句是否分配给正确人物？重点词和情绪转折是否有依据？背景是否避让信息？空间与段间状态是否一致？结尾是续接还是最终收束？同时逐字核对原文和禁止项，计算预算，核对真实参考。

生成后如能审听，检查错漏／多说、角色串声、表演强弱、遮蔽、突兀声响、次序和接缝；定位到具体段／句，保留有效部分，按 sound-design 的修复流程处理。文件下载成功只证明交付，不证明听感达标。没有实际听到时只能称为导演方案或建议提示词。

严格时长、LUFS／峰值、EQ／压缩、淡化秒数、循环点和分轨自动化应放在单独的后期目标中；只有真实编辑并测量后才报告达标。不要将这些写成 Foleyix 当前不存在的接口字段，也不要承诺从单次混合输出获取可独立调节的轨道。任何补生成仍需符合原有授权与任务恢复规则。
