# 音效、环境、音乐与修复

## 纯音效

写清声音来源与动作，再按需要补材质、质感、一次／重复、距离、空间和衰减：例如“近处厚重木门合上，一声低沉撞击后门闩轻响，短促室内回声逐渐消失”。

按钮确认音适合短促、可识别的变化；爆炸、机械启动、魔法充能适合写起音—发展—收尾。不要拿情节故事替代听觉描述，不为了电影感加入人物喊叫或音乐。原文若要求“不要人声或音乐”，完整保留；原文没设禁止项时不要擅自加一串通用限制。

游戏音效可用于 UI、脚步、武器、冲击、魔法、机关和环境。每条写一个可识别事件，明确材质、游戏语境和起止。用户要多个版本时描述有意的差异，而不是假定随机结果都会不同。网站的游戏工具支持音效批次、版本与选中 ZIP；CLI 只能逐条发出已授权的生成请求，再交付各自 WAV，不能声称提供网站批次任务的暂停／恢复／ZIP 控制。每个未知任务沿用原任务查询，不能自动补生成。

## 环境声与 ASMR

环境声是持续空间，不等于音乐：写出背景床、近／远层次和必要的稀疏事件，避免添加突兀的主角事件。真实雨声、森林、机舱背景与 ambient 纯音乐需要区别：不明确且会导致完全不同结果时问用户，不能默认混合。

ASMR 按用户需求选择耳边低声、轻敲、纸张摩擦等来源、距离和轻柔节奏。无台词的触觉声不能自动加耳语；用户要耳语时保持确切文本。左右移动或立体声请求是方向，不能保证真实双耳录音或固定声像轨迹。

循环背景先明确是持续稳定的环境还是有节奏音乐，再描述首尾连贯、避免突兀起止。自然收尾和循环边界是不同目标：纯循环时不同时要求“明显终止和弦及长淡出”。只能提供循环友好的方向，严格无缝循环需要对音频实际检查／后期编辑。

## 背景音乐

选择少量有声音意义的信息：用途、情绪、风格、主奏／配器、节奏密度、结构、是否有人声。用户只说“配乐”不一定排斥人声；要求“纯音乐／instrumental”时明确无人声、演唱、歌词、口白，必要时再排除哼唱／合唱，避免模型把人声当乐器。

项目 BGM 页面沿用 `free` 与原样文本，不存在专用 CLI `music` 模式或独立 negative prompt 字段。将所有需要的音乐方向和禁止项写入同一最终文本；不要承诺模型能以任意 BPM、音阶、音乐理论、循环点或歌曲长度严格输出。

已有请求中的风格、目标时长和禁止项需保留。允许创作时可从下列方向少量选取，不必全部填写：

| 用途 | 可听见的设计方向 |
| --- | --- |
| 专注／学习 | 稀疏重复动机、柔和电钢琴、轻鼓、低动态变化 |
| 温柔叙事 | 毛毡钢琴、留白乐句、少量弦乐 |
| 科技广告 | 合成器琶音、清楚节奏、渐进能量 |
| 风景与希望感 | 从小编制向弦乐展开、克制打击乐 |
| 紧张游戏空间 | 低持续音、稀疏脉冲、缓慢累积张力 |
| 放松 ambient 音乐 | 缓慢变化的合成器铺底、稀疏钟音，无鼓需求时才写无鼓 |

只有需要铺在对白下方时才写减少中频拥挤、对白时降低配乐存在感；独立音乐不加“对白在前景”等并不存在的内容。音乐是原创新作描述，公共样例或风格标签不是可保证复制的曲目。

## 歌曲（Song）

歌曲包含人声演唱／说唱和歌词，不是纯音乐 BGM。网站 `/song-generator` 使用同一生成链路的 `free` 与原样提示词，CLI 同样用 `--mode free`。不要自动添加“无人声、无演唱、无歌词”，也不要把歌词改成普通朗读。

在允许创作的范围内写明：曲风与情绪、主奏／节奏、人声演唱方式、歌词语言、段落顺序和需要的收尾。区分“轻柔演唱”“高能摇滚歌唱”“节奏说唱”等可听见的方向；已有要求则保持原意，不堆叠相互冲突的唱法。

用户给歌词时逐字保留，包括标点、换行、专名、数字与语言；在歌词之外写作曲、配器和唱法。可用 `[Verse]`、`[Chorus]`／`[主歌]`、`[副歌]` 分隔，它们是可选描述标签，不是应唱出的歌词或精确歌曲编辑参数。需要避免额外词句时写清只唱所给歌词，不念制作说明；用户要求重复副歌时保留明确重复顺序，不能统一套“只唱一次”。

用户要“创作一首歌”且明确让你写歌词时可以创作原创歌词；若只要求已有歌词配唱但漏了歌词，先取得必要文本。优化已有歌稿不为了押韵替换歌词。长歌词不能为了单次上限悄悄截断；给分段建议，并说明跨段旋律／演唱身份一致性需要试听和后期处理，不能保证整首无缝。

网站当前预设覆盖流行、摇滚、Hip-hop、R&B、EDM、民谣、乡村、爵士、抒情、金属、拉丁和 Synth-pop；需要最新曲风／原始样例时读当时页面预设或 `https://foleyix.com/songs/manifest.json`，不硬编码样例数量或未生成的试听结果。短样例不是完整歌曲的质量保证。歌词准确性、旋律、曲风、音色和收尾都应以真实音频核对。

背景音乐样例清单是 `https://foleyix.com/bgm/manifest.json`。选择灵感时查看 `source` 与组装说明：一首多段组装的长套曲不代表一次生成得到同样长度，不能把复制单段提示词当作复现整首套曲。

## 试听后修复

先辨认来源：用户听感反馈、可读取的实际音频，或仅凭文字推测。后者不能当作已发现的音频问题。修改优先围绕一个明确偏差，让下一次试听能判断变化是否有效；不要无依据换掉整份脚本。

| 偏差 | 可尝试的提示词修复 |
| --- | --- |
| 指令被念出或多说台词 | 外置说明，明确只读原句；逐字保留台词。不要添加新结尾句 |
| 角色串声 | 稳定说话者标签，减少同一人物冲突特征；实际绑定参考时核对顺序，不能仅加 `@voice` 假装已绑定 |
| 声音太平／情绪过度 | 把所需情绪落实到一两句、一个重音或停顿；描述克制程度，减少冲突情绪 |
| 背景盖住对白 | 明确对白为前景，背景降低存在感，特定强音效放到句间；若有后期轨道再用实际混音处理 |
| 纯音乐混入哼唱 | 明确器乐来源和排除的人声种类，同时保留原有风格与时长 |
| 歌曲变成朗读或歌词错漏 | 区分歌词与制作说明，明确演唱／说唱和段落顺序，保留歌词原文；不把错误转写当作正确歌词重写 |
| 事件顺序错乱 | 用“之前／同时／之后”拆开描述，不增加新事件 |
| 音效太杂或主音不清 | 优先核心声源，去除已授权范围内的重复指令；修改核心禁止项或删事件前必须符合用户意图 |
| 结尾突断／循环不顺 | 明确自然衰减或循环友好边界，二者择符合需求者；严格时间和循环点转入实际编辑 |

如果失败来自输入超限、缺少真实参考、服务不可用或权限，修饰文案不能解决；说明对应阻碍。提示词修复只交付修改文本，除非用户已要求重生成，不自动消耗额度。没有重新生成和审听时，表述为“建议修正版”。
